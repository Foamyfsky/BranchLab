# Data and World-Building Plan

## Data truth model

The first world combines:

| Layer | Intended source | Fidelity |
|---|---|---|
| Stations, routes, shapes | TfNSW static GTFS | Real |
| Scheduled trips/times | TfNSW static GTFS | Real |
| Buildings/basemap | OpenStreetMap-derived map tiles or GeoJSON | Real geometry, incomplete attributes |
| Passenger demand | Synthetic prior or optional calibration counts | Synthetic/calibrated |
| Operational delay | Stochastic process | Synthetic |
| Intervention effects | Executable model | Simulated |
| Realtime state | Disabled for MVP | Disabled |

## Manual dataset acquisition

Download the official Transport for NSW **Timetables Complete GTFS** ZIP and save it as:

`data/raw/tfnsw/complete_gtfs.zip`

Do not commit the large ZIP. Keep the source URL, retrieval date, resource metadata, and licence in
a small tracked provenance file generated by the importer.

The official dataset page is:

`https://opendata.transport.nsw.gov.au/dataset/timetables-complete-gtfs`

The portal may require sign-in or an API token for some download methods. The initial implementation
should accept a local ZIP path and must not depend on a runtime TfNSW API call.

## Map source

For the first online demo, use MapLibre with a keyless OpenFreeMap style and required attribution.
The official quick-start demonstrates:

`https://tiles.openfreemap.org/styles/liberty`

Codex should verify a dark/3D-compatible style at implementation time. Keep the style URL configurable:

`NEXT_PUBLIC_MAP_STYLE_URL=...`

For stronger reproducibility later, export the small demonstration area's buildings/environment into
tracked GeoJSON or host local tiles.

## Import pipeline

```text
GTFS ZIP
  → validate files and references
  → choose service date and time range
  → choose geographic subset and route set
  → group platform stops into simulation stations
  → create directed service edges
  → extract route shapes and schedules
  → derive service templates/headways
  → attach provenance and fidelity metadata
  → export versioned compact world pack
```

## Subset-selection workflow

Do not decide the final stations before inspecting the feed.

1. Importer generates a report of candidate transfer stations and active routes.
2. Codex outputs 3–5 candidate subsets with station count, routes, transfer structure, and map bounds.
3. Robert chooses one based on visual clarity and scenario potential.
4. Importer exports the final curated world.
5. The selected world receives a stable version identifier.

## Reference world

A small fictional world remains in `packages/reference-world` and test fixtures. It is used to
prove determinism, conservation, branch isolation, and UI workflows independently of the large feed.
